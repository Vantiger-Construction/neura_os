# Neura Engine milestone 1: synthetic IPC slice

This slice hardens the Rust WebSocket sidecar only. It does not complete
milestone 1, enable reflection, install a model, or admit personal sources.
The adapter remains the degraded local echo provider.

## Explicit session startup

The sidecar exits without a valid `NEURA_API_SESSION_TOKEN`. An explicit trusted
native launcher must generate a fresh cryptographically random 32-byte value,
encode it as 64 hexadecimal characters, and pass it in the child environment
for each launch. Keep the credential in RAM; never put it in a URL, command-line
argument, checked-in configuration, log, or persistent setting. Clear the
launcher's copy on session closure. This prototype relies on the launcher for
freshness and secure distribution; it does not provide OS identity attestation.

`NEURA_API_ADDR` defaults to `127.0.0.1:8787`. Only numeric IPv4 loopback
addresses and IPv6 `::1` are accepted. Wildcard, LAN, public, mapped non-loopback,
and hostname addresses fail before binding. Port `0` selects an ephemeral port.

Both endpoints require exactly one `Authorization: Bearer <session-token>`
header and a loopback peer. Credentials in query parameters do not authenticate.
Browser `Origin` headers are rejected even with a valid token. Tokens are
compared in constant time for equal-length inputs. Missing, invalid, duplicate,
or revoked credentials receive HTTP 401; disallowed peers/origins receive 403.
The server does not expose a token-creation or token-inspection endpoint.

- `GET /`: authenticated WebSocket upgrade.
- `POST /session/revoke`: revoke the entire process session, returning HTTP 204.
  It disconnects existing clients, cancels their work and rejects subsequent
  upgrades and requests. Revocation cannot be undone in this process. Any
  authenticated client can revoke the shared session; it is not an action or
  model permission. Stop the process and launch with a fresh credential to
  create a new session.

No credential or input content is emitted by sidecar diagnostics. Logging is
limited to this binary's operational info/warnings; `RUST_LOG` cannot turn on
dependency wire or HTTP header/body tracing.

## Synthetic protocol and cancellation

Protocol v1's `v`, `kind`, `id`, and `data` response framing remains intact.
`hello`, room-to-tone mapping, and diagnostics remain available to authenticated
native clients. Diagnostics explicitly report `input_scope: synthetic-only`
and the degraded echo adapter.

Only the following work request is accepted:

```json
{"v":1,"kind":"synthetic_input","data":{"fixture":"hello"}}
```

The only fixture names are `hello` and `stream`. Both select fixed,
repository-defined text; `stream` exercises interruption with 100 words.
Extra fixture fields, unknown fixture names, and the old free-form `user_text`
request return content-free errors. Caller text is never echoed or retained.
Utterance IDs are generated by the server. There is at most one active echo
task per connection; overlapping work requests receive an error.

`{"v":1,"kind":"cancel","data":{}}` closes that client's connection, cancels
generation and delivery, and discards pending output. A reconnect starts empty.
Session revocation does the same for all clients. Output already transmitted
before cancellation is observed cannot be retracted. These operations do not
flush a cancelled queue or emit a queued final completion.

The existing Flutter Console/BrainLink does not supply session authentication
or the fixture protocol and cannot use this hardened sidecar. There is no
automatic credential plumbing into production chat in this slice. Neura's
primary chat, distinct local app API, voice controls, Safe Mode and native
approval paths are unchanged. Before any UI integration admits personal inputs,
the launcher must tie revocation and shutdown to screen closure, backgrounding,
Safe Mode and recovery, and implement the vision's remaining lifecycle/consent
controls. No microphone, background cloud, personal-data ingestion, memory
admission, action dispatch, or external action path is added.

## Resource and failure contract

| Limit | Behavior |
| --- | --- |
| 4 authenticated WebSocket clients | A fifth upgrade receives HTTP 429; permits are released when connections end. |
| 4 KiB per inbound WebSocket message/frame | Oversized input closes the connection. |
| 32 outbound messages, each at most 4 KiB | Full, closed, or oversized output fails closed, disconnects the client, cancels generation, and drops pending messages. No producer waits for capacity. |
| 8 KiB transport write buffer per client, eager writes | Keeps the transport buffer bounded in addition to the application queue. |
| 2-second write deadline | A stalled or failed writer ends the connection and interrupts pending work. |

The application queue budget is at most 128 KiB per client, plus one in-flight
message and the transport buffer; four clients bound application queues to
512 KiB. These are prototype guardrails, not a measured Windows hardware budget.
Both writer and generation handles abort on owner drop; ordinary teardown also
awaits their cancellation. No connection task is intentionally detached and no
queue, token or result is persisted or replayed.

## Validation and remaining gates

Run:

```text
cargo test --manifest-path rust/Cargo.toml --locked --bin neura_api
rustfmt --edition 2021 --check rust/src/bin/neura_api.rs rust/src/ipc_tests.rs
```

The focused suite exercises actual loopback HTTP/WebSocket authorization,
rejected bindings, browser origins, revocation across multiple clients,
synthetic-only work, cancellation/reconnect, client/message limits, queue
exhaustion, revoked queued output, stalled writes and owned-task cancellation.
Transport exhaustion uses a deterministic stalled sink rather than depending on
OS socket-buffer sizes. Local Runner runs the focused suite using its existing
bounded Rust workspace and retained toolchain; storage floors, build pins,
release delivery and cleanup gates remain intact.

Supported Windows device/lifecycle evidence and the rest of milestone 1 are
still required before reflection or personal sources can be enabled. Echo tests
do not establish model quality, production Safe Mode integration, Android
lifecycle behavior, or real-model/device validation.

See [the engine vision](NEURA_ENGINE_VISION.md) for the full requirements.
