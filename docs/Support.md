## Help with Neura

Neura Companion OS is development software for everyday questions, reflection and
personal notes. Features and requirements differ between builds and platforms.
Use sample information when testing and keep a copy of anything you cannot
afford to lose. Neura is not medical care or an emergency response service.

## Contact

The app already opens feedback messages to **stevenvantiger1@gmail.com**.
It is also the email of the connected website owner. Monitoring and suitability
for public privacy/support requests have not yet been confirmed; no response
time or public support availability is promised by this draft.

In Neura, open **Settings > Send Feedback**. Describe the problem, the result
you expected and the steps that reproduce it. Inspect the email before sending;
it includes platform/OS information. If the mail composer cannot open, use the
address shown by the app in your own mail client.

For a useful bug report, include the Neura version/build if available, device
model, OS version, the feature involved, whether Safe Mode is active, and any
short error label. Redact screenshots and review diagnostic exports. Never
include API keys, passwords, private journal content, medical details, recordings
or private tester removal links.

## Journal or save problems

In **Journal Prompt**, use **Save response** and wait for the save result.
A temporary draft or guided-support writing is not the same as a saved journal
entry. Reopen a saved response to check it. If saving fails, retain your text
before leaving or restarting. Do not use cloud sync as proof that a local save
succeeded.

## Cloud AI or Offline Ollama

For cloud conversation, configure the provider in **Settings > AI Provider**,
check internet access, and review the provider/context approval before each
request. Cancelling approval does not send that attempt. A retry or fallback
requires another approval; do not paste your provider key into a support message.

The Windows **Offline Ollama** option needs separately installed Ollama, the
configured local model, an available local service and sufficient RAM. It is not
a bundled mobile model or an automatic cloud fallback. Package and fixture tests
do not establish actual inference on your laptop. Report model/service errors
using non-sensitive test text.

## Voice or microphone problems

Check device microphone/speech permissions, the selected system voice and the
feature's own controls. Platform speech can depend on installed language
components and a network connection; no universal offline-speech guarantee is
made. Text input remains the fallback.

**Safe Mode is intended to keep microphone capture off.** Leave optional ambient
capture and wake-phrase controls disabled while troubleshooting. If you observe
recording in Safe Mode, revoke Neura's microphone permission in device settings,
close the app and report the feature/build involved.

## Account and synchronization

Account and sync screens require a configured backend, successful initialization
and a supported signed-in flow. **Settings > Sync Status** exposes a manual
attempt and status. Offline, signed-out, Safe Mode, setup-required and retry
states are different outcomes. Keep your local entries and report the status;
do not repeatedly reinstall or wipe to fix a sync problem.

A missing screen can mean that this build has no backend configuration.
Automatic handoff between Windows and Android has not been verified. Signing
out does not delete cloud data. The current Profile screen does not provide a
self-service cloud-account deletion control.

## Export, deletion and privacy requests

Use **Settings > Privacy & Safety > Data Controls** for Legacy Vault export/import,
local Legacy Vault deletion or **Wipe ALL local data**. Read the confirmation
carefully. A decrypted export contains readable material; attachment files can
remain readable even in an otherwise raw vault archive.

Full local deletion cannot be undone. Check the result and restart Neura before
continuing. If deletion is incomplete, restart before retrying and report the
failed step. Copies you shared, OS backups, external files, cloud accounts and
server records are separate.

A request for cloud-account/data deletion or another privacy matter needs the
verified project contact and the actual account/backend involved. Supply only
the minimum account-identifying information through that private channel. Never
publish your request or credentials in a public issue or tester form. Public
privacy-request handling is a publication prerequisite for this draft, not a
currently verified service.

## Startup, crashes and updates

Record the short error label, build and time of the problem. If Neura offers
Safe Mode/recovery, follow its on-screen instructions. Review and redact any
log export before sending it. Do not include complete private data folders.

A configured update check can open release information; it does not establish
automatic installation or an app-store release. Use only a build destination
supplied by the project through a verified channel. The private GitHub repository
and conceptual website artwork are not public app downloads.

## Website submissions

Tester/supporter requests and investor inquiries use the existing separate
website intake. They do not create an app account or download a build. The
private removal link shown after submission deletes that submission from the
website inbox; it does not wipe the Neura app or remove emails. Keep that link
private. No private tester details belong on this support page.
